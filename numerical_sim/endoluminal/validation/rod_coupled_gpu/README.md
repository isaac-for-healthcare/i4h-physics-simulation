# Coupled rod fixture on CUDA

This validation track runs the displacement-controlled three-point bend from PR #22.
It uses one free 24-edge shaft with five fixture rows, two transverse rows at each
sliding guide and a vertical row at the loading nose. The default is two iterations
per 1 ms substep. The fixture uses the PR's shaft mass, rigidity, support span, and
nose speed.

The validation copy of the block Thomas sweep in `kernels.py` factors each modified
6×6 rod block once and solves six right-hand sides. They give the unconstrained rod
increment and its response to five unit fixture impulses. A device kernel forms the
5×5 Schur complement, then the rod and fixture increments are combined before
updating the configuration. Both Jacobians use the configuration at the start of
the iteration. Block assembly, elimination and reaction accumulation use float64.
The original RodDirect kernels supply the internal residuals, rotational Jacobians,
and final configuration update.

## Run

Run from `numerical_sim/` in the public sync worktree after installing its pinned
workspace with `uv sync --locked --group dev`. The upstream fixture comes from internal PR #22 at merge
`9799258551668ce97a63a331e43d681cc194af1b`.

```bash
V="$PWD/endoluminal/validation"
TRACK="$V/rod_coupled_gpu"

PYTHONPATH="$V" .venv/bin/python "$TRACK/run.py" --device cuda:0 \
  --wire lunderquist-extra-stiff --output /tmp/coupled-lunderquist.csv

.venv/bin/python "$TRACK/sweep.py" /tmp/coupled-cpu --device cpu
.venv/bin/python "$TRACK/sweep.py" /tmp/coupled-cuda --reference-dir /tmp/coupled-cpu
```

The CUDA runner uses the workspace stepper's graph capture by default.
`--no-cuda-graph` runs the same kernels as separate launches.
The CPU runner executes the same Warp kernels on the CPU. The sweep reads
`reference_curves.npz`, which contains all 30 simulated displacement and nose
reaction pairs from the SOFA 25.12 and Newton VBD 1.8 runs used in the PR report.
The archive keeps the original samples and contains no measured force curves.
The original trace directories are generated by the upstream scripts and
ignored by Git. To recreate the archive after [generating the upstream traces](../README.md#sofa-and-newton-comparisons),
run:

```bash
.venv/bin/python "$TRACK/sweep.py" /tmp/coupled-references --archive-references-from "$V"
```

The sweep saves each
force trace and a `comparison.csv` against the archived SOFA and Newton VBD
displacement runs. When a reference directory is supplied, it also reports
differences against the corresponding fixture traces.

The comparison uses a linear fit on samples up to 0.3 mm, the PR reporting
displacements of 4 mm for catheters and 4.407 mm for guidewires, and normalized
RMS force differences on a common 0.3–4.8 mm grid. A measured force requires a
successful factorization of both the rod blocks and the fixture matrix.

## Public sync replay

On public PR #17 head `5c5cafe`, all 15 original split-fixture CPU traces matched
the internal PR #22 replay sample for sample. All 15 coupled CPU traces also
matched the earlier internal Warp runs sample for sample. The coupled CUDA traces for
Lunderquist Extra Stiff and Cook Royal Flush 5 Fr matched their internal CUDA
counterparts sample for sample. Captured and uncaptured Lunderquist runs matched
across all 939 samples.

Both checkouts pin the same Warp and Newton revisions. The public RodDirect
computes local inverse inertia per environment and refreshes it in
`prepare()`. The one-environment fixture selects the same values as the internal
run. The production bending law, rod stiffness and Thomas sweep remain the same.
